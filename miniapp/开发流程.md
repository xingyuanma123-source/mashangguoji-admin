# 小程序开发流程

## 核心概念

- 代码只有一份。改代码 = 改这一份，不分 staging/prod。
- staging 和 prod 的区别只在“连哪个数据库”，由构建命令（读哪个 .env）决定。
- prod 上司机用的是“上次发布的正式版”，和你本地正在改的代码无关，直到你重新构建 prod 包并发布。
- 本项目用 pnpm，不要用 npm。

## 发正式版前必做的保命检查

⚠️ 正式版连哪个库，在构建那一刻就编死进包里，审核和发布不会改变它。
如果误用 staging 包发布，司机的真实报账数据会写进测试库，造成数据错乱。
发正式版前务必确认手上是 prod 包：

- 用 `pnpm run build:prod` 重新构建，构建后立即上传，中间不跑别的构建命令
- 上传前在微信开发者工具 Network 面板确认请求域名是 `rwjbladqwubgjotlygyy`（prod），若看到 `ovtnnahdqljqqkponvhu`（staging）立即停手，不要上传

## 日常开发（连 staging，安全）

1. 改代码（`miniapp/src/...`）
2. 运行 `pnpm run dev:staging` 进行 watch 开发；需要生成一次性包时运行 `pnpm run build:staging`，然后用微信开发者工具打开 `dist/weapp`
3. 连 staging 库，用测试司机 `testdriver / 123456` 登录，随便测，数据进 staging，prod 不受影响
4. 反复改、反复测，直到满意
5. 测好 → `git commit`

## 正式上线（连 prod，谨慎）

6. 运行 `pnpm run build:prod` → 微信开发者工具上传
7. 微信公众平台 → 提交审核 → 发布正式版
8. 此刻起司机才用上新功能、连真实库

⚠️ 不要用 `pnpm run build` 或 `pnpm run build:weapp` 发正式版 —— 它们不带 `--mode production`，不会读 `.env.production`，会连错环境。正式上线只用 `pnpm run build:prod`。

## 不想上线就停在第 5 步

不构建 prod 包、不发布，prod 永远是旧正式版，司机无感。

## 怎么确认当前包连哪个库

微信开发者工具 Network 面板看请求域名：

- `ovtnnahdqljqqkponvhu` = staging（测试）
- `rwjbladqwubgjotlygyy` = prod（正式）

## 注意

- 测试一律用 staging 命令，只有第 6 步发版才用 prod 命令。
- 数据库结构改动（加表/改字段）走 migration 流程（见 `docs/migrations-ledger.md`），与前端构建是两条线。
- 本项目用 pnpm，不要用 npm。
